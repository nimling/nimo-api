One conversion now hands the readers of an API ready made requests for the two clients they reach for first.

## Postman collection

`convert --postman-output <dir>` writes `postman.json`, a Postman v2.1 collection with one folder per tag and one request per operation. The server becomes the `baseUrl` variable, path parameters become path variables filled from their examples, and optional query parameters are included but switched off.

## Hurl archive

`convert --hurl-output <dir>` writes `hurl.zip` holding `api.hurl`, one entry per operation, and `variables.env` for `hurl --variables-file`. Each entry expects the first `2xx` status the operation documents.

## Request bodies

A body is the example of the request when it has one. Without an example it is built from the schema, taking each property's example, default, first enum value, format and type in that order, so a `uuid`, an `email` or a `date-time` reads as one.

## Authentication

| Scheme in the specification | Postman | hurl |
| --- | --- | --- |
| OAuth2 client credentials | OAuth2 with `tokenUrl`, `clientId` and `clientSecret` variables | a token request first, captured as `token` |
| API key in a header | API key with the `apiKey` variable | the header with `api_key` |
| HTTP bearer | bearer with the `token` variable | `Authorization: Bearer` with `token` |
| HTTP basic | basic with `username` and `password` | basic with `username` and `password` |

## OAuth flows in the bundled spec

The `flows` of an OAuth2 security scheme, with their token URL and scopes, are now carried into the written `spec.json`. They were dropped before.

## GitHub Action

The action takes `postman-output-dir` and `hurl-output-dir` for the two new outputs.
